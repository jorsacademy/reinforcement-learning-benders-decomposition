# RL formulation

## Decision epoch

One decision epoch occurs after:

1. the current Benders master is solved;
2. every scenario recourse LP is solved exactly;
3. the incumbent and relative gap are updated;
4. all violated scenario cuts are known.

The agent therefore acts on fully observed solver-progress information for the declared benchmark.

## State

The raw observation contains the master solution, bounds, incumbent, cut pool, violations, solver time, and stall counter. Tabular Q-learning receives five categorical features:

| Component | Buckets |
| --- | --- |
| Relative gap | `<=1%`, `<=5%`, `<=20%`, `>20%` |
| Violated-scenario fraction | none, `<=25%`, `<=75%`, `>75%` |
| Violation concentration | diffuse, intermediate, concentrated |
| Cuts per scenario | `<1`, `<3`, `>=3` |
| Stall count | `0`, `1`, `>=2` |

The Cartesian product contains `4 × 4 × 3 × 3 × 3 = 432` states.

## Actions

The action set is ordered:

```text
one, quarter, half, all
```

An action selects a prefix of cuts ranked by normalized violation. Under Q-value ties, the policy chooses the larger batch. An untrained zero-valued checkpoint therefore degrades to the conservative `all` action.

## Transition

Selected cuts are added to the master. The next master and all next recourse subproblems are solved exactly. The new observation is then discretized.

The state transition is stochastic across generated problem instances, but deterministic for a fixed instance, solver build, and floating-point execution path.

## Reward

The reward combines normalized gap reduction with transparent work penalties:

```text
progress_weight * normalized_gap_improvement
- iteration_cost
- selected_cut_cost * selected_cut_count
- master_cut_cost * cumulative_cut_count
+ terminal_bonus
- truncation_penalty, when applicable
```

The reward intentionally excludes wall-clock time. Small optimization instances produce noisy microbenchmarks, and training directly on those timings can teach machine-specific artifacts. Runtime remains an evaluation metric.

## Learning rule

The policy uses epsilon-greedy tabular Q-learning:

```text
Q(s,a) <- Q(s,a) + alpha * [r + gamma * max_a' Q(s',a') - Q(s,a)]
```

Exploration decays linearly from `epsilon_start` to `epsilon_end` across episodes. Randomness is generated by a local NumPy generator with an explicit seed.

## Checkpoint

A checkpoint stores:

- the complete Q tensor;
- checkpoint schema version;
- action order;
- tensor shape;
- training instance names;
- Q-learning hyperparameters;
- optional research-protocol metadata.

Load-time validation rejects incompatible action orders, shapes, nonfinite Q values, and unknown checkpoint versions.
